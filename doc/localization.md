# Localization

FxDesktop localization is ARB-first and Flutter-native. Runtime widgets use the
generated `FxDesktopLocalizations` class, while `.po` and `.pot` files are
translator bridge formats.

## App Integration

Use the normal Flutter localization shape:

```dart
MaterialApp(
  localizationsDelegates: FxDesktopLocalizations.localizationsDelegates,
  supportedLocales: FxDesktopLocalizations.supportedLocales,
  locale: selectedLocale,
  home: const FxLocalizationGallery(),
);
```

`FxDesktopLocalizations.localizationsDelegates` includes the FxDesktop delegate
plus Flutter's Material, Cupertino, and Widgets delegates.

## Bundled Locales

`0.5.0` includes:

- English: `en`
- Thai: `th`
- Japanese: `ja`
- Nepali: `ne`

Translations are seeded for framework validation and examples. Product teams
should still review translated wording before using it as final product copy.

## Text Ownership

FxDesktop localizes framework-owned strings:

- component empty states and default error states
- color picker dialog chrome
- date/time empty prompts
- lookup empty states
- undo labels generated by table components
- accessibility labels generated by components
- localization gallery chrome
- ribbon toolbar chrome
- ribbon designer chrome and inspector labels

Host apps continue to own business text:

- field labels supplied by app code
- table row values
- option captions supplied by app code
- validation messages supplied by app code

For model-owned text that must travel through JSON, use `FxLocalizedText`.
Ribbon definitions use `FxRibbonLocalizedText`, which is a type alias to the
same model, so command captions, tooltips, semantic labels, tab labels, group
labels, and designer-authored names can travel through JSON with independent
per-context translations.

## ARB Source

Source files live in `lib/l10n/`:

```text
lib/l10n/fx_desktop_en.arb
lib/l10n/fx_desktop_th.arb
lib/l10n/fx_desktop_ja.arb
lib/l10n/fx_desktop_ne.arb
```

Generated Dart localizations are checked in under `lib/src/l10n/` so pub.dev
users do not depend on hidden local generated files.

When adding a string:

- add the English ARB value
- add translator metadata with `description` and `context`
- add all bundled locale values
- keep duplicate English strings as separate keys when context differs
- run `flutter gen-l10n`
- run `dart run tool/fx_l10n.dart audit`

## PO And POT Bridge

Export a POT template:

```bash
dart run tool/fx_l10n.dart export-pot \
  --output doc/localization/fx_desktop.pot
```

Export a locale PO file:

```bash
dart run tool/fx_l10n.dart export-po \
  --locale th \
  --output doc/localization/po-import-example-th.po
```

Import translated PO back to ARB:

```bash
dart run tool/fx_l10n.dart import-po \
  --input doc/localization/po-import-example-th.po \
  --locale th \
  --output lib/l10n/fx_desktop_th.arb
```

The importer uses PO `msgctxt`, not `msgid`, as the key identity. This is
required because duplicate English words can need different translations in
different component contexts.

## Audit

Run:

```bash
dart run tool/fx_l10n.dart audit
```

The audit checks:

- all four ARB files exist
- all locales have the same message keys
- template keys have unique PO contexts
- placeholders match across translations
- PO examples parse and preserve known contexts

## Gallery And Screenshots

`FxLocalizationGallery` is the one-window proof surface for localization. It
shows form controls, choice controls, navigation, date/time/color controls,
ListBox/Grid, state views, and PO duplicate-context examples.

Localization gallery screenshots live under:

```text

```

The screenshot set covers English, Thai, Japanese, Nepali, and an RTL layout
smoke view.

Ribbon release screenshots live under:

```text

```

The ribbon sample includes English, Thai, Japanese, and Nepali command captions
